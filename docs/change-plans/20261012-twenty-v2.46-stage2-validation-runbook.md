# Stage 2 — safe local source validation (Twenty 2.46.0)

**Purpose:** reproducible offline-first (no CRM data mutation) checks before any isolated Test deployment. This runbook is **not a claim that tests have passed**. Execute in a clean checkout of `permavent/port-v2.46.0`, not old `main`; never run migrations on Live.

## 1. Prerequisites — local development machine

The target source pins **Node 24.16.0** in `.nvmrc`, **Yarn 4.13.0** in `package.json`/`.yarnrc.yml`. The accepted source base is `twenty/v2.46.0`; use its Yarn lockfile without unrelated dependency upgrades.

```bash
git fetch origin
git switch permavent/port-v2.46.0
git pull --ff-only origin permavent/port-v2.46.0
git status --short
nvm install
nvm use
node --version
corepack yarn --version
corepack yarn install --immutable
```

**Gate:** ensure `git status --short` is empty before proceeding; do not discard local work. `corepack yarn install` should use the repository's package manager and lockfile. Expected Node 24.16.0 / Yarn 4.13.0. Yarn install/build may need network to fetch declared packages. Package manager changes are not authorised.

## 2. Target code and SDK static gate

```bash
corepack yarn nx run twenty-sdk:typecheck
corepack yarn nx run twenty-front-component-renderer:typecheck
corepack yarn nx run twenty-server:typecheck
corepack yarn nx run twenty-front:typecheck
```

The `twenty-server:typecheck` target has upstream `^build` dependencies. Diagnose each failure: (a) missing/generated metadata, (b) stale TypeScript import/API, (c) infrastructure/config, and avoid papering over it with `skipLibCheck`, casts or broad dependency upgrades.

The front `PageLayout` update input gained `defaultTabToFocusOnMobileAndSidePanelId`. Regeneration of its generated GraphQL metadata is required in an **isolated development/Test server**, not a Live server. Re-run front typecheck after that generation.

## 3. Focused unit tests

The Twenty server declares `twenty-server:jest` as a Jest command target (cwd `packages/twenty-server`). Use it or invoke Jest from the server package directory, e.g.:

```bash
cd packages/twenty-server
corepack yarn jest --runInBand --runTestsByPath \
  src/engine/core-modules/code-interpreter/drivers/__tests__/permavent-internal.driver.spec.ts \
  src/engine/twenty-orm/utils/__tests__/resolve-role-ids-from-auth-context.util.spec.ts
cd ../..
```

Run additional existing tests of the actual changed features (Permavent Sales Scope, delegated actor resolver, User Audit, Opening Tab and widget behaviour) identified in the [198-file matrix](https://github.com/ssypchenko/twenty/blob/permavent/upgrade-v2.46.0-preparation/docs/change-plans/evidence/20261012-stage1-port-disposition.json). Do not substitute old `mcp-protocol.service.spec.ts` tests: those targeted a deleted read-only mechanism and have been removed.

## 5. Separate isolated Test acceptance (not part of the local static gate)

- MCP: native Twenty tools work under ordinary **user/application role rights, including authorised create/update/delete/upsert**. Confirm that an unprivileged actor is denied and cannot access a different workspace. **No project-specific read-only scope**.
- Code Interpreter: production `LOCAL` is disallowed; `PERMAVENT_INTERNAL` uses a separately isolated Python runner, configured URL/secret and `actorKey` session isolation. E2B remains unused unless explicitly approved.
- Reports and Audit: authenticated user + trusted delegated key, role-bound ERP sales scopes, redacted margin for Sales Rep, Security-only audit screen, event logging, retention. Audit schema/migration must be verified on an isolated clone before deployment.
- Page Layout: opening tab create/choose/save/clear, active-tab fallback, desktop/mobile side panel; generated GraphQL metadata and old workspace custom objects retained.
- SDK + four Git Apps: `workspaceMemberId` is context metadata, **not an authorization token**. Server permissions come from validated request claims and role checks. Upgrade Apps' SDK engine range only after compatible builds and deployed-server version check.
- Gate 0 recovery: official image digest/provenance, separate Test writer isolation, verified backup+restore of PostgreSQL/files/secrets. **Never overwrite Live database from Test.**
