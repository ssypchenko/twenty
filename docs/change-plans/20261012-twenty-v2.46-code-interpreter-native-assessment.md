# Twenty v2.46.0 — Code Interpreter / built-in MCP compatibility decision

**Date:** 2026-10-12. **Review basis:** exact Twenty upstream source tag `twenty/v2.46.0` = `9070979232c4f37165108a2eb5a4042e0cfdc3d6`, accepted Permavent `main` = `7546570ec82fcd7d1a3b7d7599c161d11c044424`, current `permavent/port-v2.46.0`. No server access, typecheck, Docker tests or external sandbox connection tests were available in this review.

## Decision

**Reuse Twenty's own MCP endpoint and general-purpose Code Interpreter tool, NOT a separately owned Permavent MCP server.** Keep the existing Permavent internal sandbox driver only as an optional execution backend for company-operated isolated Python in Production. This must not be confused with the independent **Python Permavent ERP Management MCP**, which has a different repository and is **out of scope**.

Do **not** merge the old 2.35.2 MCP service/guard/controller wholesale. Treat the old read-only privilege restriction as an *independent security acceptance requirement*. **Do not enable CRM-accessible Code Interpreter for Production or even a connected Test workspace until token access is correctly constrained and negative tests pass.** No part of this review authorises E2B provisioning or moving company CRM data to a third-party sandbox.

## Targeted fixes written during this source check

1. `67d24afccad7cfc88834bd8d56f282264137084e`: restored missing mandatory/optional `PERMAVENT_CODE_INTERPRETER_RUNNER_URL`, `PERMAVENT_CODE_INTERPRETER_RUNNER_TOKEN` and `PERMAVENT_CODE_INTERPRETER_RUNNER_REQUEST_TIMEOUT_MS` config variables with original validation and sensitive token handling. The previous Stage 2 source port had copied the factory without these config declarations, an obvious type/runtime mismatch. Default Code Interpreter remains DISABLED in Production.
2. `1a4b563057ed06d4e77e6d5c7566e3d481c2d66f`: adapted the internal driver to the new v2.46 `ExecutionContext.actorKey`. A thread switching from actor A to actor B now must terminate its prior remote Python session before starting another; on remote deletion failure the request aborts rather than reusing a prior actor kernel. Added two Jest cases (same-actor continuity / different-actor isolation / failed deletion); **tests authored, not executed**. No external runner touched.

## Validation matrix — run on isolated development/Test after source build

1. **Build prerequisites:** Node `24.16.0` (both `.nvmrc`), Yarn `4.13.0`, Nx target pinned; do not mass-upgrade deps simply because newer ones exist. Run full affected server `typecheck`, impacted Jest suites and build. `git status` clean check.
2. **Native endpoint/auth:** MCP health/initialize, tools/list and catalogue for least-privileged actor, legitimate `find_many_companies` and `group_by`, user/application identity and workspace isolation, invalid/expired token denial.
3. **Read-only isolation:** from a real sandbox-issued token, attempts to `create_one_company`, `update_one_company`, `delete_one_company`, `upsert_many_companies` and equivalent REST/GraphQL access must fail server-side. Altering Python helper text alone is insufficient; direct HTTP bypass is possible. **Currently not proven or implemented**. No mutations should be sent to Production for this test.
4. **Sandbox backend:** `LOCAL` in production must refuse execution; `E2B` requires separate supplier/privacy approval; `PERMAVENT_INTERNAL` must reject missing URL/token, use bearer token to runner, sanitize file paths, isolate actor sessions, correctly stream output, and release sessions on expiry.
5. **Cross-principal tests:** same thread/new user or application identity must NOT share Python state. Concurrent requests, runner failures and reauth must preserve isolation.
6. **Use-case functionality:** read-only analysis of CRM records, chart files/CSV upload, repeated session, timeout, per-user permissions, actor audit attribution. Do not claim compatibility solely from compiling.

## Open engineering decision / minimum follow-up

The existing `PERMAVENT_INTERNAL` driver is only an **execution isolation** boundary. It is **not** an MCP authorization boundary because `code-interpreter-tool.ts` currently still hands it a normal privileged access token. Therefore, before Code Interpreter can be enabled for live CRM data, implement and test a **minimal server-enforced read-only token/authorization scope** against the **new 2.46 native MCP endpoint**, preserving native protocol/tools, OR prove an upstream-supported constrained-role/token configuration meets the same requirement. Do not port 2.35 `jwt.auth.strategy`, `mcp-protocol.service` wholesale.

Current safe state is `CODE_INTERPRETER_TYPE=DISABLED` by default in Production. Merely selecting `PERMAVENT_INTERNAL` without the above auth work is **NO-GO**. This is a source/security requirement; no claim that native E2B or the external runner was launched.

**Unchanged:** `main`, pristine `permavent/upstream-v2.46.0`, production and Test server, Python ERP MCP, dependency versions.
