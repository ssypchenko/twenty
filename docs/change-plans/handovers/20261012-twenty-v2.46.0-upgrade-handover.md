## 12. Stage 2 Code Interpreter design clarification and source security audit — 2026-10-12

Owner decision: **reuse the built-in Twenty 2.46 MCP API and Code Interpreter mechanisms wherever they meet requirements, not a separate Twenty MCP server; retain our own runner only if required.** This is separate from the independent Python ERP Management MCP, which is out of scope.

Verified against exact upstream and current port source: native `LOCAL` Code Interpreter executes Python on the Twenty host and is prohibited in Production; native `E2B` uses an external sandbox/provider and should not be silently enabled or introduce transfer of sensitive CRM data. The native Python `TWENTY_MCP_HELPER` explicitly supports create/update/upsert and gets a standard short-lived user/application JWT; role checks still apply but our **historical read-only sandbox boundary is not enforced**. Therefore **no Code Interpreter enablement for live CRM data before an actual denied-write smoke test**. Keep native Twenty MCP endpoint and tool handling; add only a minimal proven read-only server-side token/role limitation if required, not old broad MCP subsystem replay.
