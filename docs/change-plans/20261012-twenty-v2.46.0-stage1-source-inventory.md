- `git compare` equivalent via GitHub connector, accepted source `main` vs pristine `2.35.2`: **21 custom commits**, **198 distinct changed files**, **97 modified**, **99 added**, **2 deleted**. Every path mapped to ≥1 accepted commit (0 unmapped).
- Read SHA for **each of 198** path names against target `twenty/v2.46.0`. Read base SHA for **each of the 99** previously existing paths from pristine commit. Same-path blob SHA equality only proves that pristine upstream file contents stayed identical, not that the Permavent patch will apply.

## Stage 2 sequence with decision gates

1. **Source/toolchain preflight**: obtain target tree as local Git checkout, run `git diff --find-renames` for affected paths and `git merge-base`; inspect 2.35-exclusive 46 upstream files and target migration replacements. Use exact pinned Node 24.16, Yarn 4.13, Nx 22.7.8 unless officially justified updates. Repair target-specific script refs instead of changing old script version strings.
2. **Lower-risk branded email + flags**: minimal diffs, rendered output tests; preserve default-off `PERMAVENT_SECURITY_RLS_ENABLED` and per-environment flags.
3. **Security/ERP block**: delegated key/actor context, MCP read-only catalog/guard, core Sales Scope and all query/REST/ORM paths. Require forbidden-read/write and actor-spoof negative tests before moving on. Upstream record sharing can introduce new paths; no relaxing checks to make compile pass.
4. **Audit, Weekly Report and Code Interpreter**: port custom modules, migration/cron/logic-function events, Live-only isolated runner. Verify retained audit entries and four Custom-app functions.
5. **UI and SDK**: wide-panel rewrite on target resize system; overview widgets; workspace member SDK context; opening tab settings and persistence integrated with new Page Layout rendering. Regenerate GraphQL/client metadata against a running target server, verify explicit null and migration ordering.
6. **Build/test verification and Apps handoff**: target TypeScript/Nx/server/unit tests, source build, security scope and boundaries; separately update four Apps and fix broken local SDK links. Never just widen their engine range.

Keep all three repo branch roles distinct: clean upstream base remains untouched; implementation changes go into `permavent/port-v2.46.0`; evidence/handover into `permavent/upgrade-v2.46.0-preparation` (or mirrored to port branch as appropriate).
