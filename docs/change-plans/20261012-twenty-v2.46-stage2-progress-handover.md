## Source verification addendum — built-in MCP vs internal Code Interpreter, 2026-10-12

The owner clarified that the Twenty fork does not run a separate MCP server. Confirmed by reading exact upstream 2.46.0 and fork source. Decision: **reuse native Twenty MCP endpoint; do not port all old MCP patches**. The independent Python Permavent ERP MCP is out of scope. The native Twenty Code Interpreter's `LOCAL` driver is development-only and explicitly blocked in Production. `E2B` is isolated but external: do not change deployment or transmit data to this third party without separate approval. Optional company-operated `PERMAVENT_INTERNAL` stays as our own sandbox backend, using native Twenty Code Interpreter integration.

**Security finding:** native `TWENTY_MCP_HELPER` in 2.46 supports `create`, `update`, `upsert`, and the native `McpProtocolService` filters only explicitly excluded dangerous tools, not all database writes. The default short-lived Code Interpreter token is a full `ACCESS`/`APPLICATION_ACCESS` token, not a sandbox read-only token. The owner explicitly accepted default user/application CRUD permissions on 2026-10-12, so read-only is **not a project requirement**. Do not add sandbox-specific scope restrictions or restore old MCP patches. Check actual role-bound writes and refusals instead.

**Two focused fixes actually pushed:** `67d24afccad7cfc88834bd8d56f282264137084e` reintroduces three missing Permavent runner config declarations with validation and sensitive token handling; `1a4b563057ed06d4e77e6d5c7566e3d481c2d66f` isolates persistent internal Python runner sessions using new `actorKey`, with two Jest tests authored but **not run**. [Detailed source audit and precise follow-up gates](20261012-twenty-v2.46-code-interpreter-native-assessment.md). No dependency changes or server deployment. This Stage 2 handover file was initially made at source head `9d398963`; read the subsequent addendum for current details.
